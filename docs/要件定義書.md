# 要件定義書

## アプリ概要

- サブスクを一元管理し、解約・継続の意思決定を補助するアプリ
- コンセプト：**「サブスクを、惰性ではなく選択にする。そして、忘れない。」**
- 守り（管理・解約忘れ防止）と攻め（見直し促進・意思決定補助）の二軸で構成する

## 背景

- 定期購読など、解約を忘れて無駄な出費がある。能動的に調査しないと想起・発覚しないことも
- 普段使わないメールアドレスでサブスクを登録すると、更新通知が埋もれて存在自体を忘れる
- クレジットカードの明細に何のサービスか分からない請求が紛れ込む場合がある
- 低額のサブスクが積み重なり、合計支出が把握できないまま膨らみがち
- 現状維持バイアス・サンクコスト効果・損失回避心理により、使っていなくても解約できない傾向がある
- 優先度が低く、コストパフォーマンス的に不要なものが含まれている懸念がある

## システム要件

1. WebアプリケーションとしてリリースしPhase2以降でPWA化する
1. 認証機能を持ち、ユーザーごとにデータを管理する（JWTによる自前認証）
1. データベースはPostgreSQL（Neon上のサーバーレスPostgres）を使用する
1. DBアクセスはPhase1〜2はnode-postgres（pg）の生SQLで実装し、Phase3以降でPrismaを導入する
1. 定期処理（通知・チェック送信）はアプリ層のnode-cronで実装する
1. メール通知はResendを使用する
1. AI機能はGemini APIを使用する（コスパコメント生成・自然言語登録）
1. HTTPSを使用する（主要ホスティングサービスで自動対応、PWA化の前提条件）
1. レスポンシブデザイン（モバイルファースト）、Tailwind CSSで実装
1. 月の使用金額・年の使用金額・年間平均支出を算出して表示する

## 機能要件

### 1. モード選択

- 個人モードと世帯モードを選択できる
- 世帯モードでは複数ユーザーでサブスクを共有管理できる
- モードはあとから変更可能

### 2. サブスク登録

- 手入力での登録（サービス名・金額・開始日・請求サイクル・継続予定レベル）
- 自然言語での登録（AI解析。例：「Notionを月2000円で先月から使ってる」）
- スクショOCRによる登録補助（Phase2以降、外部APIを使用）
- 請求サイクルはmonthly・yearly・カスタム周期に対応（カスタムは開始日必須）
- 継続予定レベルは任意入力
- アプリ導入時点で既に契約中のサブスクも登録できる

### 3. 更新通知

- 更新日の事前にメールで通知する
  - monthly：1週間前・1日前
  - yearly：1ヶ月前・1週間前・1日前
- 通知のオンオフをサブスクごとに設定可能
- 通知メールに「継続する」「解約する」「1ヶ月保留」の3択ボタンを添付する
- 「継続する」は能動的に押す設計（デフォルトで継続にならない）
- Phase2（PWA化）以降はプッシュ通知に移行する

### 4. チェックイン機能

- 隔週でチェックイン用メールを送信し、チェック画面に直接遷移させる（URLパラメータで起動）
- 通知経由でアプリを開いた場合のみチェック画面を自動表示する（通常起動時は押しつけない）
- カード形式のUI（単語帳のめくり型）で1枚につき2問に絞る
  - 直近の使用時期（今月・1ヶ月前・2ヶ月前…）
  - 使用レベル（強・中・弱）
- 1回あたりのチェック件数は最大3件
- 優先度キューで対象を決定する（スコアが低いもの・未チェック期間が長いものを優先）
- 月内に全件チェックできなかった分は次回サイクルで優先表示する

### 5. コスパスコア

- 使用頻度・継続期間・金額・継続予定レベルを変数にアルゴリズムでスコアを算出する
- スコア算出はアルゴリズム（ルールベース）で行い、一貫性を担保する
- チェックイン回答後にスコアランキングをリアルタイムで反映する
- 月次で折れ線グラフにスコア推移を記録・表示する（株のチャートイメージ）
- スコアが低いサブスクにAIが一言コメントを生成する（30字以内、Gemini API使用）
- ワーストN件を「見直し候補」として表示する（件数はユーザーが設定、デフォルト3件）
- 見直し候補の表示閾値（スコア○点以下）をユーザーが設定できる（デフォルト40点以下）

### 6. 見直し促進

- 見直し候補には以下を表示する
  - 「このまま継続するとあと年間XX円かかります」
  - 登録からの累計支払額
  - 今後1年・3年の支払予測額
- 「解約すると年間XX円が手元に残ります」という形で損失ではなく利得として表現する

### 7. 可視化

- 月額・年額の合計表示
- カテゴリ別の内訳グラフ
- コスパスコアの推移（折れ線グラフ、月次更新）
- サブスクごとの累計支払額・今後の支払予測額

### 8. 値上げ通知

- 主要サービス（Netflix・Amazon Prime・Spotify等）のみ対応
- 対象サービスの値上げ情報を静的DBで管理する
- 値上げ検知時にメールで通知する

### 9. 解約手順案内

- 主要サービスの解約手順・解約URL・解約難易度を静的DBで管理・表示する
- 解約URLへの直接遷移ボタンを設ける
- DB未登録サービスは公式サイト検索リンクを表示する

### 10. データ管理

- 解約済みサブスクのアーカイブ機能
- データのCSVエクスポート（有料機能候補）

## 非機能要件

### 1. 可用性

- サービス稼働率：99.5%以上を目標とする
- 定期メンテナンスは深夜帯（0:00〜5:00）に実施する
- DB（Neon）の障害時はユーザーにメール通知する

### 2. 性能・拡張性

- ページの初期表示は3秒以内を目標とする
- ユーザー数が増加した場合もVercel・Neonのスケールアップ（オートスケール）で対応する
- node-cronによる定期処理はユーザー数増加に伴い分散処理・ジョブキューを検討する

### 3. 運用・保守性

- Neonの自動バックアップ（ポイントインタイムリストア）を有効にする
- エラーログを記録し、障害発生時に原因を特定できる状態を維持する
- 本番・開発環境を分離する
- ユーザの認知的負荷を減らすため、Netflix,apple musicなどの大手サブスクリプション商品はデフォルトで選択肢を表示
- その他サブスクリプションは値上げや改訂の情報更新コストを考慮し、実装しない。

### 4. 移行性

- Phase1（Web app）からPhase2（PWA）への移行時、既存ユーザーデータを引き継ぐ
- DBスキーマ変更時はマイグレーションファイルで管理する
- 将来のネイティブアプリ化を考慮し、APIはREST形式で設計する

### 5. セキュリティ

- 認証はJWT（JSON Web Token）で自前実装する（メール認証）
- ユーザーデータは他ユーザーから参照できないよう、アプリケーション層でアクセス制御する（クエリにuser_id条件を必須化）
- HTTPS通信を必須とする
- パスワードはハッシュ化して保存する（bcrypt等）
- メール通知のリンクにはワンタイムトークンを使用する

### 6. システム環境・エコロジー

- ホスティングはVercel（フロントエンド）・Neon（DB）を使用する。バックエンド（Express）はRender/Fly.io等の常駐型ホスティングを使用する
- 外部APIはGemini API・Resendを使用する
- 開発環境はNode.js、DBはNeonの開発ブランチ（またはローカルPostgres）を使用する

## 開発フェーズ

### Phase1：Web app（MVP）

- 手入力によるサブスク登録
- 更新通知（メール）
- チェックイン機能
- コスパスコア・可視化
- 見直し候補表示

### Phase2：PWA化

- プッシュ通知への移行
- Service Workerの実装
- スクショOCRによる登録補助

### Phase3：ネイティブアプリ化

- iOS・Androidアプリとしてリリース

## 技術スタック

| 領域             | 技術                                          |
| ---------------- | --------------------------------------------- |
| 言語             | TypeScript、SQL（PostgreSQL方言）             |
| フロントエンド   | React（Next.js）、Tailwind CSS                |
| バックエンド     | Node.js + Express                             |
| DBアクセス       | node-postgres（pg）の生SQL → Phase3でPrisma   |
| データベース     | PostgreSQL（Neon）                            |
| 認証             | JWT（自前実装）                               |
| 定期処理         | node-cron                                     |
| メール通知       | Resend                                        |
| AI               | Gemini API                                    |
| ホスティング     | Vercel（フロント）、Neon（DB）、Render等（API） |
